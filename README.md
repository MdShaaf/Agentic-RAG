# 📚 Agentic-RAG — Chat With Your Documents

A local, privacy-friendly **Retrieval-Augmented Generation (RAG)** app. Upload your PDFs, index them into a FAISS vector store, and ask questions in a chat interface. Answers are generated by a local LLM (via **Ollama**) strictly from the retrieved context, and every answer shows the exact source chunks (file name + page) that backed it.

Everything runs on your machine: no API keys, no data leaves your computer.

---

## ✨ Features

- **Streamlit chat UI** with a sidebar for uploading and indexing PDFs
- **Source transparency**: each answer comes with an expandable list of the retrieved chunks, labelled with file name and page number
- **Selectable search strategy**: switch between **Semantic**, **Keyword**, and **Hybrid** search from the UI, each with a short in-app explanation of when to use it
- **Local embeddings** with `sentence-transformers` (`all-MiniLM-L6-v2`, normalized vectors) stored in **FAISS**
- **Hybrid retrieval + reranking**: FAISS semantic search + BM25 keyword search, fused with an ensemble retriever and reranked by the `BAAI/bge-reranker-base` cross-encoder (semantic-only and keyword-only modes also available)
- **Grounded generation**: the default prompt instructs the LLM to answer only from the provided context and to say so when the answer isn't there
- **Tunable answers**: an **Advanced** panel lets you set the LLM temperature and edit the answer instructions (with a one-click reset to the default)
- **Multi-format loaders**: PDF, TXT, DOCX, and CSV, with consistent metadata (source, path, file type, doc id, chunk id)
- **Local LLM** through Ollama, so you can swap models freely

## 🏗️ How It Works

```
 Upload PDFs
     │
     ▼
 Load documents  ──►  Split into chunks (1000 chars, 200 overlap)
                              │
                              ▼
                   Embed (all-MiniLM-L6-v2)  ──►  FAISS index
                                                      │
 Question ──►  Semantic / Keyword / Hybrid search  ◄──┘
                              │
                              ▼
                   Cross-encoder reranking
                              │
                              ▼
               Build context from retrieved chunks
                              │
                              ▼
              Ollama LLM (answer only from context)
                              │
                              ▼
                 Answer  +  expandable sources
```

1. **Ingest** — PDFs are written to a temp folder and loaded with LangChain loaders; metadata is attached to every page.
2. **Chunk** — `RecursiveCharacterTextSplitter` splits pages into 1000-character chunks with 200 characters of overlap and adds `chunk_id` / `parent_doc_id` metadata.
3. **Embed & index** — chunks are embedded with `all-MiniLM-L6-v2` and indexed in FAISS.
4. **Retrieve & rerank** — the question is searched using the strategy you pick in the UI, then the retrieved candidates (up to 10 per retriever) are scored and sorted by a cross-encoder reranker.
5. **Generate** — the reranked chunks are joined into a context block and passed to the local LLM together with your answer instructions (by default, a strict "use only this context" prompt) and the chosen temperature.
6. **Cite** — the retrieved chunks are shown under the answer with file name and page.

## 🧰 Tech Stack

| Layer | Tool |
|---|---|
| Language | Python ≥ 3.13 |
| UI | Streamlit |
| Orchestration / loaders | LangChain (`langchain`, `langchain-community`, `langchain-text-splitters`) |
| Embeddings | `sentence-transformers` — `all-MiniLM-L6-v2` |
| Vector store | FAISS (`faiss-cpu`) |
| Keyword search | BM25 (`rank-bm25`) |
| Reranker | `BAAI/bge-reranker-base` (cross-encoder) |
| LLM | Ollama — `llama3.2:1b` |
| Document parsing | `pypdf`, `python-docx`, `unstructured`, `pandas` |

## 🚀 Getting Started

### Prerequisites

- Python 3.13 or newer
- [Ollama](https://ollama.com/) installed and running

### 1. Clone the repository

```bash
git clone https://github.com/MdShaaf/Agentic-RAG.git
cd Agentic-RAG
```

### 2. Install dependencies

Using [uv](https://github.com/astral-sh/uv) (recommended):

```bash
uv venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
uv pip install -r pyproject.toml
```

Some modules also import packages that aren't listed in `pyproject.toml` yet. Install them too:

```bash
uv pip install langchain-classic rank-bm25 unstructured
```

### 3. Pull the LLM

```bash
ollama pull llama3.2:1b
```

Make sure the Ollama server is running (`ollama serve`) before starting the app.

### 4. Run the app

```bash
streamlit run app.py
```

Then in the browser:

1. Upload one or more PDFs in the sidebar
2. Click **⚙️ Process PDFs**
3. Pick a **search strategy** (Semantic, Keyword, or Hybrid)
4. Optionally open **⚙️ Advanced** in the sidebar to change the temperature or the answer instructions
5. Ask questions in the chat box and expand **📎 Sources** to see what each answer was based on

> The first run downloads the embedding and reranker models from Hugging Face, so it can take a few minutes.

## ⚙️ Configuration

| Setting | Where | Default |
|---|---|---|
| LLM model | `src/Agentic_RAG.py` | `llama3.2:1b` |
| Temperature | **Advanced** slider in `app.py` | `0.1` (range 0.0–1.0) |
| Answer instructions | **Advanced** text box in `app.py` (`DEFAULT_INSTRUCTIONS` in `src/Agentic_RAG.py`) | "Answer using only the provided context; say so if the answer isn't there" |
| Chunk size / overlap | `src/Chunking.py` | `1000` / `200` |
| Embedding model | `src/Embedding.py` | `all-MiniLM-L6-v2` |
| Reranker model | `src/similarity_reranker.py` | `BAAI/bge-reranker-base` |
| Search strategy | Radio selector in `app.py` | Semantic Search |

Lower temperatures give more factual, consistent answers; higher ones give more varied wording. For better answer quality overall, try a larger Ollama model such as `llama3.1` (change the model name in `src/Agentic_RAG.py`).

## ⚠️ Limitations

- The chat app currently uploads **PDFs only** (the loaders for TXT, DOCX, and CSV exist in `src/` but aren't exposed in the UI)
- Answer quality depends heavily on chunking quality and on the size of the local model (the default 1B model is fast but limited)
- The index is rebuilt in memory each time you click **Process PDFs**; it isn't persisted between sessions
- No conversation memory: each question is answered independently
- Hallucinations are reduced by the grounded prompt but not eliminated; if you edit the answer instructions and drop the "only use the context" rule, answers may no longer match the Sources panel
- Small local models can follow long or complex custom instructions poorly
